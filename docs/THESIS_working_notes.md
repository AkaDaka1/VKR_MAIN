# VKR_MAIN — краткий разбор для текстовой части диплома

*Рабочий черновик: сюда можно копировать ответы ассистента по разделам ВКР.*

## Тема диплома (согласовать с кафедрой)

Формулировка: **«Разработка генератора иммерсивного театра»**. Смысловой центр — **конвейер в n8n с нейросетью** для генерации/доработки сценариев (вход: ТЗ к сценарию, интеграция через вебхук и API), далее — **поддерживающая ИС** (клиенты сотрудника и зрителя, БД, роли) из VKR_MAIN.

## Тема и предметная область

**VKR_MAIN** — **информационная система управления театром** (а по охвату сущностей — сетью театров/франшизой): учёт **сотрудников, театров, залов, франшиз**, репертуар (**сценарии, акты, части**), **показов**, **клиентов и билетов**, **голосований** (обычных и VIP), **оборудования и услуг** с **арендой**. **Файл ТЗ сценария** передаётся в **n8n** (нейросетевой workflow), ответ API сохраняет как результат — см. `N8N_TZ_WEBHOOK_URL`, `api/api.py` (`process_scenario_tz_via_n8n`).

## Цель и характер системы (как в дипломе)

- **Основной продукт по теме:** генератор (нейросеть в n8n + интеграция с API по ТЗ сценария). **Сопутствующая:** автоматизация учёта театра (справочники, афиша, билеты, ресурсы).
- **Автоматизировать** хранение и ведение данных театрального предприятия (справочники, афиша, билеты, ресурсы).
- **Централизовать доступ** к данным через **HTTP API** (вместо прямого подключения клиентов к БД), с **аутентификацией (JWT)**, **хешированием паролей (bcrypt)** и **ролевой моделью** (администратор, менеджер, сценарист, партнёр франшизы, базовый пользователь и т.д.).
- **Два типа пользователей по каналу доступа:**
  - **сотрудники** — десктоп-клиент на **Python + PySide6 (Qt)**: выборки, поиск, CRUD, дашборд, ТЗ сценариев;
  - **зрители/клиенты (MVP)** — **Android** (**Kotlin, Jetpack Compose**): публичные API — регистрация/вход, список театров, сеансы, схема мест, **бронирования**.

## Технический стек (кратко для раздела «Средства реализации»)

| Уровень | Технологии |
|--------|------------|
| Сервер | **FastAPI**, **SQLAlchemy**, **Pydantic**, **PostgreSQL** |
| Сотрудники (клиент) | **Python**, **PySide6**, репозитории поверх `requests` |
| Клиенты (мобильный) | **Kotlin**, **Jetpack Compose**, **Retrofit**, **Hilt** |
| n8n / сценарии | Webhook, workflow (нейросетевой узел), связь с `process_scenario_tz_via_n8n` |
| Развёртывание | `docker-compose` (БД + API), отдельно n8n по инструкции, переменные окружения, тесты **pytest** |

## Архитектура (для схемы/описания)

Клиент (Qt или Android) → **JSON по HTTP** → **FastAPI** → **CRUD** → **PostgreSQL**. Документация в репозитории прямо отражает это разделение (см. `docs/ARCHITECTURE.md`).

## О чём можно писать «актуальность» и «новизну»

- **Иммерсивный театр** + снижение трудоёмкости **сценарного контура** за счёт **нейросети** в **n8n** при сохранении учёта и контроля артефактов.
- Переход от **прямого доступа к БД** к **многоуровневой архитектуре с API** (`docs/COMPARISON.md`).
- **Единый backend** — настольный и мобильный клиенты, **RBAC**.
