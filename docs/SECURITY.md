# Рекомендации по безопасности

## Обзор

Этот документ описывает лучшие практики безопасности для приложения управления театром, особенно в контексте нового API-слоя.

## 1. Управление учетными данными

### Хранение паролей
- Все пароли должны хешироваться с использованием bcrypt или аналогичного алгоритма
- Никогда не храните пароли в открытом виде
- Используйте соли (salts) при хешировании

### Учетные данные базы данных
- Не храните учетные данные в коде (hardcoded)
- Используйте переменные окружения или безопасные хранилища
- Регулярно меняйте пароли от базы данных

## 2. Аутентификация и авторизация

### JWT-токены
- Используйте JWT-токены с коротким сроком действия
- Реализуйте механизм обновления токенов
- Храните токены безопасно на стороне клиента

### Проверка прав доступа
- Реализуйте RBAC (Role-Based Access Control)
- Проверяйте права доступа для каждой операции
- Разделяйте права на чтение, запись и администрирование

## 3. Защита от атак

### SQL-инъекции
- Используйте параметризованные запросы
- Валидируйте все входящие данные
- Используйте ORM (SQLAlchemy) для дополнительной защиты

### XSS-атаки
- Санитизируйте вывод данных
- Используйте HTTPS для всех соединений
- Устанавливайте безопасные заголовки HTTP

### CSRF-атаки
- Используйте CSRF-токены для форм
- Проверяйте заголовок Origin и Referer
- Реализуйте политику SameSite для кук

## 4. Логирование и мониторинг

### Логирование
- Логируйте все попытки аутентификации
- Записывайте важные операции с данными
- Не логируйте чувствительные данные (пароли, токены)

### Мониторинг
- Отслеживайте аномальную активность
- Установите лимиты на количество запросов
- Настройте оповещения о подозрительных действиях

## 5. Безопасная конфигурация

### Настройки FastAPI
- Используйте CORS только для доверенных доменов
- Валидируйте все входящие данные с помощью Pydantic
- Настройте безопасные заголовки

### Настройки базы данных
- Используйте отдельных пользователей для разных частей приложения
- Ограничьте права доступа к таблицам
- Регулярно обновляйте СУБД

## 6. Обновления и патчи

### Регулярные обновления
- Поддерживайте зависимости в актуальном состоянии
- Следите за уязвимостями в используемых библиотеках
- Проводите регулярные аудиты безопасности

## 7. Резервное копирование

### Регулярные бэкапы
- Создавайте регулярные резервные копии базы данных
- Храните бэкапы в зашифрованном виде
- Проверяйте возможность восстановления из бэкапов

## 8. Обработка ошибок

### Безопасная обработка ошибок
- Не раскрывайте внутреннюю информацию об ошибке клиенту
- Используйте общие сообщения об ошибках
- Логируйте подробности ошибок на сервере

## 9. Шифрование данных

### Чувствительные данные
- Шифруйте чувствительные данные при хранении
- Используйте HTTPS для всех соединений
- Рассмотрите шифрование данных на уровне базы данных

## 10. Проверка безопасности

### Регулярные проверки
- Проводите пентесты регулярно
- Используйте автоматические сканеры уязвимостей
- Обучайте разработчиков безопасному программированию

## 11. Загружаемые файлы и секреты в рабочей копии

- Каталог **`data/scenario_tz/`** на сервере API хранит документы ТЗ сценариев; в git он не коммитится (см. `.gitignore`). Ограничивайте доступ к каталогу на диске и делайте бэкапы вместе с БД, если эти файлы критичны.
- Файл **`.env`** с `DB_PASSWORD`, `SECRET_KEY`, URL n8n и т.д. не должен попадать в репозиторий.
- В **`api/config.py`** для локальной разработки заданы значения по умолчанию (в т.ч. пароль БД); в продакшене обязательно переопределяйте их переменными окружения.
