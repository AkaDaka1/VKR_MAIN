10. Структурное программирование. Представление основных структур программирования: циклы, ветвление.

Структурное программирование — подход к написанию программ, где управление потоком выполнения строится из ограниченного набора понятных конструкций, а код организован в блоки/подпрограммы без «хаотичных прыжков».

Исторически идея — уйти от большого количества goto и сделать программы:
- более читаемыми;
- более проверяемыми;
- более надежными и удобными для сопровождения.

Три базовые управляющие структуры
1) Последовательность
Команды выполняются одна за другой.
Пример из ИС: получить запрос → проверить токен → прочитать данные из БД → вернуть ответ.

2) Ветвление (выбор)
Позволяет выполнить разные действия в зависимости от условия.
Формы:
- if / else
- switch / case (множественный выбор)

Примеры из ИС:
- если пользователь имеет роль ADMIN — разрешить операцию, иначе запретить;
- если входные данные невалидны — вернуть ошибку 400, иначе продолжить обработку.

3) Цикл (повторение)
Выполнение блока кода несколько раз.
Основные виды:
- while (цикл с предусловием) — выполняется, пока условие истинно.
- do…while (с постусловием) — тело выполняется хотя бы один раз.
- for (цикл с параметром) — обычно удобен для счетчика/индекса.
- foreach / for..of (перебор коллекции) — удобно для списков.

Примеры из ИС:
- перебрать строки результата запроса и сформировать отчет;
- обработать список заказов, вычисляя итог по каждому;
- повторить попытку запроса к внешнему сервису (retry) ограниченное число раз.

Вложенные структуры
Структуры можно вкладывать:
- if внутри цикла (например, фильтрация элементов);
- цикл внутри if (например, выполнить обработку списка только при наличии данных).

Практические требования к использованию ветвлений и циклов в ИС
1) Ясные условия и границы
Важно избегать бесконечных циклов и «сложных» условий.
Для сетевых ИС: всегда задавать таймауты и лимиты повторных попыток.

2) Обработка ошибок
Внутри ветвлений/циклов должна быть предусмотрена обработка исключительных ситуаций:
- неверные данные;
- отсутствие записи в БД;
- недоступность внешнего API;
- ограничения по правам.

3) Читаемость и декомпозиция
Если ветвление слишком большое или цикл делает «слишком много», лучше выделить подзадачи в функции/методы.
Это повышает тестируемость и снижает риск ошибок.

4) Сложность алгоритма
В ИС легко «случайно» получить медленную обработку (например, вложенный цикл + запрос к БД внутри — классическая ошибка N+1).
Структурное программирование не гарантирует оптимальность, но помогает увидеть структуру и улучшить ее.

Итог
Структурное программирование опирается на последовательность, ветвление и циклы. На практике это базовый фундамент, на котором строятся и ООП‑программы, и сервисы ИС (API, обработчики событий, задачи по расписанию).
