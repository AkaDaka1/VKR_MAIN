7. Понятие алгоритма и его свойства. Классы алгоритмических задач.

Алгоритм — это точное и конечное описание действий, которое переводит исходные данные (вход) в результат (выход). В программировании алгоритм реализуется в виде кода, но сам по себе алгоритм — это идея/последовательность шагов, не привязанная к конкретному языку.

Примеры из области информационных систем:
- алгоритм авторизации пользователя (проверка логина/пароля, выдача токена);
- алгоритм обработки запроса в API (валидация → бизнес-логика → запись в БД → ответ клиенту);
- алгоритм поиска записи в таблице/индексе (например, по ключу).

Основные свойства алгоритма
1) Дискретность (пошаговость)
Алгоритм состоит из отдельных шагов, которые выполняются в определенном порядке.

2) Определенность (детерминированность)
Каждый шаг сформулирован однозначно: при одинаковом входе получаем одинаковый результат (если не используется случайность и внешние факторы).

3) Конечность
Алгоритм должен завершаться за конечное число шагов и выдавать результат. Для ИС это важно: запрос не должен «висеть» бесконечно.

4) Результативность
После выполнения алгоритма мы получаем понятный выход: число, строку, структуру данных, запись в БД, сформированный отчет и т.д.

5) Массовость (применимость к классу задач)
Алгоритм должен работать не для одного единственного набора данных, а для множества входов одного типа. Например, «рассчитать итог заказа» для любого заказа.

6) Эффективность (практичность)
Алгоритм должен быть выполним на реальном компьютере за разумное время и с разумным расходом памяти. В ИС это проявляется в требованиях к времени ответа API, нагрузке на БД, стоимости вычислений.

Классы алгоритмических задач (часто встречающиеся группы)
1) Вычислительные задачи
Цель — вычислить значение по формуле/правилу. Пример: расчет скидки, налогов, рейтингов.

2) Задачи обработки данных (преобразования)
Сортировка, группировка, фильтрация, агрегация. Пример: построение отчета по продажам, выборка по условиям.

3) Задачи поиска
Поиск элемента в структуре данных, поиск пути, поиск по тексту. Пример: поиск пользователя по email; полнотекстовый поиск по описанию.

4) Задачи принятия решения (распознавание/классификация/проверка)
Алгоритм отвечает «да/нет» или выбирает класс. Пример: проверка прав доступа; валидация входных данных.

5) Задачи оптимизации
Нужно найти «лучшее» решение по критерию (минимум/максимум). Пример: распределение ресурсов, планирование расписания, подбор маршрута.

6) Комбинаторные задачи
Перебор вариантов, составление комбинаций/размещений. Часто сложные по вычислениям. Пример: генерация вариантов сценария/маршрутов при ограничениях.

7) Графовые задачи
Работа с графами (вершины/ребра). Пример: зависимости задач в проекте, маршрутизация, социальные связи.

8) Строковые и текстовые задачи
Поиск подстроки, сравнение, нормализация, разбор форматов (JSON, XML). Пример: обработка логов, парсинг сообщений.

Связь с дисциплиной «Информационные системы и технологии»
Для ИС важны не только «правильные шаги», но и требования к эффективности и надежности: алгоритм должен быть корректным, масштабируемым (работать на больших данных), безопасным (не допускать утечек/ошибок доступа) и устойчивым к ошибкам входных данных.
