17. Технологические процессы разработки программного обеспечения.

Технологический процесс разработки ПО — это организованный набор работ, ролей, артефактов и правил, по которым создают, проверяют, внедряют и сопровождают программный продукт.

Для направления «Информационные системы и технологии» это особенно важно, потому что ИС обычно:
- многокомпонентные (клиент, сервер, БД, интеграции);
- развиваются долго и командой;
- требуют надежности, безопасности и документирования.

Жизненный цикл ПО (общая логика)
1) Инициация и анализ
- постановка цели и границ системы;
- анализ предметной области;
- сбор требований: функциональные (что делает) и нефункциональные (скорость, безопасность, надежность);
- определение заинтересованных сторон (заказчик, пользователи, администраторы).

Артефакты: описание требований, пользовательские сценарии, ограничения, критерии приемки.

2) Проектирование
- архитектура (например, клиент‑сервер, монолит/микросервисы);
- проектирование данных (ER‑модель, схемы БД);
- проектирование интерфейсов и API (контракты, форматы ошибок);
- проектирование безопасности (модель ролей, права, хранение секретов).

Артефакты: архитектурная схема, спецификация API, модели данных, прототипы UI.

3) Реализация (кодирование)
- разработка по задачам;
- соблюдение стандартов кодирования;
- управление версиями (Git), ветвление, code review.

Артефакты: исходный код, миграции БД, конфигурации, скрипты.

4) Тестирование и верификация
Цель — убедиться, что система корректна и надежна.
Виды:
- модульное (unit);
- интеграционное (БД, внешние сервисы);
- системное (end‑to‑end);
- нагрузочное;
- безопасность (проверка уязвимостей).

Артефакты: тест‑кейсы, отчеты, результаты прогона CI.

5) Внедрение (релиз/деплой)
- подготовка окружений (dev/test/prod);
- сборка и доставка (CI/CD);
- миграции БД;
- настройка мониторинга и логирования;
- план отката (rollback).

Артефакты: релиз‑ноты, инструкции деплоя, конфиги окружений.

6) Эксплуатация и сопровождение
- мониторинг, реагирование на инциденты;
- исправление ошибок и выпуск обновлений;
- поддержка пользователей;
- развитие функционала.

Артефакты: база знаний, журналы инцидентов, backlog задач.

Модели и методологии разработки (как организуют процесс)
1) Каскадная (Waterfall)
Этапы идут последовательно: требования → проект → реализация → тест → внедрение.
Плюсы: понятная структура, удобно для строго регламентированных проектов.
Минусы: сложно менять требования, поздняя обратная связь.

2) Итеративная/инкрементальная
Система создается частями и улучшается итерациями.
Плюсы: можно быстрее показать результат и корректировать требования.

3) Agile-подходы (Scrum, Kanban)
Scrum: спринты, планирование, демо, ретроспектива, роли (PO, Scrum Master, команда).
Kanban: непрерывный поток задач, лимиты WIP, фокус на времени прохождения.
Для ИС часто подходит Agile: требования меняются, важна быстрая обратная связь.

Процессы обеспечения качества и управляемости (что обычно обязательно в ИС)
- управление требованиями и изменениями (change management);
- управление конфигурациями и версиями (Git, версии API);
- code review;
- CI/CD (автоматическая сборка, тесты, линтеры);
- управление рисками;
- документирование (особенно API и модели данных);
- безопасность (SDLC/DevSecOps: секреты, зависимости, уязвимости).

Роли в типичном процессе разработки ИС
- аналитик (requirements);
- архитектор;
- backend/frontend/mobile разработчики;
- инженер по тестированию (QA);
- DevOps/инженер по инфраструктуре;
- администратор БД;
- менеджер/тимлид.

Итог
Технологический процесс разработки ПО — это не только «писать код», а полный цикл: требования → проектирование → реализация → тестирование → внедрение → сопровождение. Для информационных систем ключевыми становятся процессы качества (тесты, ревью, CI/CD), надежности (мониторинг, бэкапы) и безопасности (роль‑ориентированный доступ, защита данных).
