13. Методы передачи параметров в подпрограммы.

Подпрограмма (функция/процедура/метод) часто принимает параметры — входные значения, с которыми она работает. Способ передачи параметров влияет на:
- можно ли менять аргумент внутри функции и отразится ли это снаружи;
- производительность (копирование больших объектов);
- безопасность и читаемость кода.

Основные методы передачи параметров
1) Передача по значению (pass-by-value)
В функцию передается копия значения.
- Изменение параметра внутри функции не меняет переменную снаружи.
Пример идеи: передали число count — внутри можно менять localCount, а внешняя переменная не изменится.

Плюсы: проще понимать, меньше побочных эффектов.
Минусы: для больших структур копирование может быть дорогим (хотя языки оптимизируют).

2) Передача по ссылке (pass-by-reference)
В функцию передается ссылка/адрес на исходный объект, и функция может менять его «на месте».
- Изменения внутри видны снаружи.

Пример из ИС: функция заполняет объект ответа, добавляет поля в структуру результата.

Плюсы: эффективно для больших объектов, можно возвращать несколько результатов через параметры.
Минусы: больше побочных эффектов, сложнее отлаживать, нужно следить за состоянием.

3) Передача по адресу / через указатель (pass-by-pointer)
Похожий смысл на «по ссылке», но явно: в параметре передается указатель.
Типично для C/C++.

Плюсы: контроль и эффективность.
Минусы: риск ошибок (null, висячие указатели, выход за границы).

4) Передача по значению объекта ссылки (частый случай в Java/C#/Python/JS)
Важно различать термины:
Во многих языках фактически передается значение (копия) ссылки на объект, поэтому:
- можно изменить внутреннее состояние объекта (поля) — это увидят снаружи;
- но если «переназначить» параметр на другой объект, это не поменяет внешнюю переменную.

Это часто описывают как «pass-by-sharing».

5) Передача по имени (pass-by-name) и по необходимости (lazy)
Редко в прикладных ЯП общего назначения как базовый механизм, но встречается в отдельных языках/конструкциях.
Суть: параметр ведет себя как выражение, которое вычисляется при обращении.

Связанные практические понятия (часто спрашивают вместе)
1) Входные/выходные параметры (in/out/inout)
Некоторые языки и API явно различают:
- in: только вход;
- out: функция обязуется заполнить значение;
- inout: и вход, и выход.
В ИС это помогает ясно показать, где есть побочный эффект.

2) Необязательные параметры и значения по умолчанию
Полезно для API функций: уменьшают количество перегрузок и упрощают вызовы.
Пример: limit=50, offset=0 для постраничного вывода.

3) Именованные параметры
Повышают читаемость, особенно когда много параметров одного типа.

4) Вариативные параметры (varargs)
Можно передать переменное число аргументов (например, список полей для сортировки).

5) Передача неизменяемых объектов (immutability)
Чтобы повысить надежность, часто делают объекты неизменяемыми или передают «только для чтения».
Это снижает побочные эффекты и помогает при многопоточности.

Как это связано с разработкой ИС
- Для больших DTO/моделей важно понимать: копируется ли объект или передается ссылка, чтобы не получить неожиданные изменения.
- Для надежности API и бизнес‑логики важно минимизировать побочные эффекты: использовать возврат результата вместо изменения входных параметров, где это возможно.
- Для производительности важно избегать лишних копирований больших структур и строк.
