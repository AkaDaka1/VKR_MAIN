План практики: задачи, сроки и полученные результаты

Срок выполнения: 13.04.2026
Полученные результаты: согласовано направление работ и приоритеты этапов внедрения. Зафиксированы ожидаемые результаты практики в виде промежуточных артефактов (проектирование, реализация, тестирование, подготовка сопроводительных материалов). План работы на практику приведен в форму, пригодную для сдачи.

2. Задача: уточнение постановки задачи и требований к системе (функциональные, нефункциональные, требования безопасности).
Срок выполнения: 15.04.2026
Полученные результаты: сформирован перечень требований, отражающий ключевую механику проекта: сбор голосования зрителей, передача данных в нейросетевой контур и сохранение сценарных артефактов. Критерии проверки сформулированы в табличном виде для последующей верификации в главе по тестированию. Уточнены ограничения по безопасности: разделение внутреннего и публичного контура, хранение токенов и управление секретами.

3. Задача: проектирование структуры данных (ключевые сущности и связи), выделение сценарных артефактов (ТЗ, результаты обработки).
Срок выполнения: 17.04.2026
Полученные результаты: определены кластеры сущностей, соответствующие предметной области театра и показу. Сформирована ER-диаграмма в сжатом виде для наглядного представления связей между сценарием, показом, зрителем и голосованием. Отдельно зафиксировано разделение структурированных полей в базе данных и файлового хранилища для ТЗ и результата обработки.

4. Задача: проектирование архитектуры комплекса и каналов взаимодействия компонентов (desktop/mobile, API, БД, n8n, файловое хранилище).
Срок выполнения: 19.04.2026
Полученные результаты: выбрана многоуровневая схема, где клиентские приложения обращаются к данным только через серверное API. На рисунке общей архитектуры отражены связи между настольным и мобильным клиентами, сервером, базой данных и внешним оркестратором n8n. Описано назначение файлового хранилища как контейнера больших текстовых артефактов сценария.

5. Задача: проектирование интеграции с n8n и нейросетевым контуром (контракт вебхука, вход/выход, ошибки, тайм-ауты).
Срок выполнения: 21.04.2026
Полученные результаты: определено, что логика нейросетевого конвейера выносится в настраиваемый внешний процесс, а API обеспечивает стабильный контракт «запуск–ответ». Зафиксированы требования к длительным операциям и обработке сбоев сети при недоступности внешнего сервиса. Описаны состояния обработки, необходимые для прозрачности работы сценариста и администратора.

6. Задача: реализация серверной части — модели данных, маршруты API, авторизация по ролям, хранение сценарных файлов и результатов.
Срок выполнения: 24.04.2026
Полученные результаты: реализованы основные CRUD-операции и разделение публичных и внутренних маршрутов. Настроены механизмы аутентификации и ролевой модели для ограничения операций по полномочиям. Обеспечено сохранение метаданных сценарных файлов и их связь с записями сценария.

7. Задача: реализация вызова n8n по вебхуку и обработки результата (передача файла, сохранение ответа, статусы обработки).
Срок выполнения: 26.04.2026
Полученные результаты: реализован сетевой вызов внешнего вебхука с тайм-аутом и фиксацией результата в хранилище сценарного артефакта. Предусмотрена корректная трактовка ошибок сети и неуспешных кодов ответа без разрушения остальной функциональности. Пользовательский интерфейс сотрудника получает понятный статус обработки для повторных запусков.

8. Задача: реализация настольного приложения сотрудников (выборки, поиск, редактирование, диалог «ТЗ сценария»).
Срок выполнения: 29.04.2026
Полученные результаты: обеспечен типовой сценарий работы с табличными выборками и поиском по текущей таблице. Реализован отдельный диалог загрузки ТЗ и управления обработкой через внешний контур. Для иллюстрации подготовлены скриншоты ключевых экранов для включения в поясняющие материалы.

9. Задача: реализация мобильного клиента зрителя (вход, афиша/показы, схема мест, бронирование, мои бронирования).
Срок выполнения: 02.05.2026
Полученные результаты: реализован пользовательский маршрут зрителя от аутентификации до бронирования места и просмотра собственных бронирований. Сетевой слой выделен в отдельные репозитории для снижения дублирования логики интерфейса. Подготовлены скриншоты экранов входа и бронирования для наглядного подтверждения реализации.

Срок выполнения: 04.05.2026
Полученные результаты: настроен запуск автоматических тестов и сформирована таблица базовых тестовых сценариев с ожидаемыми результатами. Проведена ручная верификация пути обработки ТЗ при поднятом n8n и корректной конфигурации вебхука. Зафиксировано, что качество художественного текста оценивается сценаристом, а инженерная проверка охватывает стабильность интеграции и ошибки сети.
