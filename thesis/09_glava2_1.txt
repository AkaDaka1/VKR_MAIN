2.1 Функциональные и нефункциональные требования к системе

Функциональные требования включают три контура. Первый — внутренний контур сотрудников: ведение сущностей театра (сотрудники, площадки, сценарии, акты, части, показы, билеты, услуги, аренды, голосования и иные справочники), поиск, редактирование и контроль статусов. Второй — сценарно-генеративный контур: загрузка ТЗ, настройка точек ветвления, запуск генерации, сохранение результата, просмотр истории версий. Третий — зрительский контур: регистрация и вход, просмотр показов, выбор места, участие в голосовании в момент спектакля, получение результата продолжения в рамках пользовательского сценария.

Ключевое функциональное требование проекта: система должна принимать результат голосования зрителей по вариантам продолжения и использовать его как обязательный вход нейросетевого workflow для генерации следующего фрагмента сценария. При этом требуется хранить связку данных: идентификатор показа, точка ветвления, вариант-победитель, время голосования, сгенерированный результат и статус обработки.

Нефункциональные требования: интерактивность UI, устойчивость API при сбоях сети, прозрачные сообщения об ошибках, настраиваемые тайм-ауты внешнего workflow, сопровождаемость за счёт разделения слоёв, конфигурируемость через переменные окружения, возможность контейнерного развёртывания. Для этапа показа добавляется требование по времени отклика генерации: обработка должна завершаться за интервал, допустимый для театрального ритма, иначе система должна предложить запасной сценарий.

Требования безопасности: JWT-аутентификация, ролевая авторизация, ограничение запуска генерации по ролям, защита персональных данных, защита секретов интеграции с n8n, аудит действий в сценарном контуре. Совокупность этих требований служит базой для проектирования взаимодействий, структуры данных и архитектуры.
